# 执行指令模板

所有 `{路径}` 必须替换为项目扫描后确认的真实路径。指令只能引用原 STEP，不得改写需求、任务或完成标志。

这些执行模板只用于用户另行显式启动的 `standalone` 执行编排，不得由总控 `orchestrated` 模式自动调用。

## 模板 A：生成里程碑草案

```text
请读取已确认的 PRD、开发 STEP 和项目规范，只做执行编排。

输入：
- PRD：{路径}
- STEP：{路径}
- 项目规范：{路径列表}
- 用户指定阶段或节奏：{内容；未指定则写“无”}

根据依赖、可独立验收成果、风险、冲突和用户约束，提出 M1…Mn 草案。
阶段数量不得套用固定模板。列出每个阶段的目标、STEP、顺序、可并行候选、
明确排除项、验收方式、临时契约位置和闸门，并解释划分依据。

不要修改任何文件，等待用户确认。
```

## 模板 B：执行单个 STEP

```text
当前里程碑：{编号与名称}
本次只执行：{STEP 编号}

必读：
- 实施计划：{路径}
- STEP 原文：{路径和编号}
- 进度记录：{路径}
- 项目规范：{路径列表}

严格执行原 STEP 的任务、范围和完成标志，不新增、删减或重新解释需求。
如发现冲突、遗漏或不可执行条件，停止开发并报告证据，不修改源文档。

交付：
- 改动文件列表
- 对应每条原完成标志的验证证据
- 契约增量草稿
- 阻塞、风险或偏差
- 进度记录更新
```

## 模板 C：执行已确认批次

```text
当前里程碑：{编号与名称}
本次批次：{批次名}
包含 STEP：{编号列表}
合批依据：{实施计划中的已确认依据}

每个 STEP 必须保持独立范围、改动记录、验证结果和契约增量。
不得跨越里程碑，不得因合批而合并或改写 STEP 内容。
任一 STEP 出现依赖或冲突时，暂停受影响项并更新阻塞记录。
```

## 模板 D：里程碑验收

```text
只验收里程碑 {编号与名称}，不要开发新功能。

依据：
- 实施计划：{路径}
- STEP 原文：{路径}
- 进度与验证证据：{路径}

逐条输出：通过 / 部分通过 / 未通过，并附证据。
只有本里程碑全部 STEP 完成且验收条件满足时才能通过闸门。
未通过时列出缺口并停留在当前里程碑。
```

## 模板 E：汇总里程碑临时契约

```text
里程碑 {编号与名称} 已通过验收。
读取本里程碑全部 STEP 的契约增量，按项目既有规范汇总到：{临时契约路径}。

只记录本里程碑的新增、变更、删除、兼容和迁移影响。
标注来源 STEP，不修改正式契约文档。
```

## 模板 F：整合正式契约

```text
全部里程碑已完成并通过总验收。

读取：
- 所有里程碑临时契约：{路径列表}
- 项目正式契约：{路径}
- 项目契约规范：{路径}

按现有结构统一整合所有有效变更。更新语义相同的已有条目，避免重复；
检查跨阶段冲突、废弃项、兼容和迁移说明。保留临时契约作为快照，
并在进度记录 {路径} 中登记整合结果。
```

## STEP 契约增量格式

```markdown
### {STEP 编号} 契约增量

- 变更类型：新增 / 修改 / 删除 / 无契约变化
- 契约对象：{数据、接口、事件、配置、权限、枚举或项目定义的其他对象}
- 变更内容：{准确描述}
- 兼容或迁移影响：{无或具体说明}
- 验证证据：{测试、命令或检查结果}
```
